# M0 — Repo, window, empty 5×5 grid

Breakdown of M0 from `implementation_plan.md` §5 (est. 1–2 hours total).

## Decisions made

- **Coordinate order: `(col, row)`.** Never mix. Anywhere a cell is passed around, col comes first.
- **Screen offset lives in the view.** `board.py` knows only the grid's size in cells; pixels are the view's business.

This puts the pixel↔cell conversions in the view rather than in `board.py`, since they can't be computed without the offset and cell size:

| File | Owns |
|---|---|
| `board.py` (pure logic, no `import pygame`) | `width`, `height` in cells; `in_bounds(col, row)`; later `is_adjacent(a, b)`, occupancy |
| `BoardView` | `origin_x` / `origin_y`, `cell_size`; `cell_to_rect(col, row)`; `pixel_to_cell(x, y)` |

The conversion methods are just arithmetic and never touch a surface, so they stay unit-testable even though they live on the view. (Alternative if that feels wrong: a small pygame-free `GridGeometry` class holding offset + cell size + the two conversions, which the view composes. Tidier, more ceremony — worth revisiting if Run from Red's larger boards need to reuse it.)

### M0.c — Grid math, no drawing (~20 min)
- [x] `board.py` with grid dimensions and `in_bounds`
- [x] `cell_to_rect(col, row)` on the view
- [x] `pixel_to_cell(x, y)` on the view, returning `None` for a miss

Highest-leverage step in M0. Get the conversions right and M1's click detection is three lines; get them wrong and off-by-one bugs eat hours.

**Two traps:**

1. **Guard bounds *after* dividing, not before.** Integer division rounds toward zero, so a click 5px left of the grid gives `-5 // 64 == -1`, not `0` — checking only the upper bound lets an outside click land silently in column 0.
2. **Be consistent about the miss value.** `None` is the obvious choice, but then every caller needs `is not None` — because `if cell:` is false for the perfectly valid cell `(0, 0)`.
